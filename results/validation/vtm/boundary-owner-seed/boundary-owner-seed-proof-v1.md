# Private current-owner candidate seeding

The previous owner is only a hint. Before traversal, a nonnegative owner below both the current active prefix and array length is evaluated using the current sample and current site coordinates. For a free-site query it must still be unoccupied. A finite computed squared distance strictly below the original 1e300 search limit initializes the result; otherwise the original initialization remains. Traversal, strict box pruning, child ordering, leaf distance arithmetic and lowest-ID equal-distance tie handling are copied from the original function.

An eligible current site gives a mathematical upper bound on nearest distance. No old distance, old position, surface generation or prior acceptance is reused. Current hierarchy bounds and active filtering remain necessary. The existing hierarchy encloses its current binary32 sites by componentwise min/max; nonnegative squared-norm operations support the existing pruning rule. Compiler floating-point context still requires direct original/seeded ID and distance-bit comparisons; the argument alone is not a claim of compiled bitwise equivalence.

The accumulation kernel reads the old owner before clearing its output slot. Failed, zero-weight or invalid-sizing slots retain the original clearing/error behavior. The private constructor fills both existing owner arrays with -1 before any graph executes; its internal capture records work but does not read those arrays. No new persistent arrays or replay copies/launches are added. Surface changes, point movement, new sampling and active-count changes can make a hint poor but cannot turn it into a stale accepted nearest result.

This is private instrumentation at main74601fc. The prototype replaces boundary accumulation only inside the experimental process. Production adoption would retain independent diagram/Delaunay and standalone boundary/core defaults, with explicit private ownership and initialization. Sixty direct cases (12,000 queries) match IDs and distance bits across stale/out-of-range hints, active prefixes, occupied sites, ties, duplicates, extreme scales and nonfinite queries. Complete-solve work, outputs, performance, actual paired trajectory queries and captured changing-input memory safety remain adoption gates.
