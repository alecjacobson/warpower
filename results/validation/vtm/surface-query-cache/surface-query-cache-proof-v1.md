# Private exact surface-query cache

A per-consumer table maps the exact three float64 center bit patterns to a row of the preceding call. The stored ray result is reusable only if that preceding row actually evaluated the same default, non-excluded-face material-side query. A stored nearest result is reusable only if that row actually queried nearest distance and the float64 search-limit bits match too. Successful hits, misses, ambiguity codes, face IDs, hit-point bits and squared distances are kept verbatim. Geometry, retention thresholds, volumes and quality still execute on current input.

The input surface and its traversal metadata must be unchanged. The prototype resets every attached table at domain refit and fresh full-mesher execution. Any classifier error prevents its next table from being populated. Each current call first writes a separate result buffer; it reads only the completed previous buffer/table. After the classifier finishes, device copies refresh the previous state, the table is cleared, and a separate device build kernel publishes indices. There is no query/build race. Equal center keys choose the minimum previous row; a row without a requested result causes a fresh query. Bounded probe exhaustion is a cache miss, never acceptance. The insertion and lookup hash compare all center bits; hash equality alone does not permit reuse.

All buffers exist before capture. There are no host input comparisons or reads in execution. The prototype adds buffers and graph copies/build kernels, whose complete-solve cost must be measured. The observer found almost no stable row positions, so the cache uses exact keys rather than row indices. Its results cover the immediately preceding call, not a persistent history of arbitrary older queries.

This is private experiment code, not production adoption. Its monkeypatch currently attaches to all extraction constructors for experimentation; production integration would restrict it to private VTM consumers and retain ordinary public/standalone defaults. Public entry boundaries and refit/producer ownership must be made explicit before adoption. The domain-refit/fresh-solve guards are necessary, and matching a center alone cannot reuse a bounded nearest miss at a different cutoff. Floating-point expression context still needs direct original-kernel and trajectory comparison despite the mathematical memoization argument.
